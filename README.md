# A workbook for reviewing a family relationship map

A relationship diagram is easier to discuss when its author can explain why each person, line, and note appears. This workbook is a practical companion to that review. It provides a small set of worksheets and review questions for people preparing an educational example or a carefully scoped personal history diagram. It is not a clinical assessment form, an identity database, or a substitute for consent and appropriate professional advice.

The workbook uses fictional examples only. It is prepared on behalf of the Genogram Maker project with AI assistance, not as an independent product evaluation or a report about a real family. You can complete the review on paper, in a spreadsheet, or beside a drawing application. The worksheets describe decisions to make; they do not claim that a particular application automatically enforces those decisions.

## 1. Write the purpose in one sentence

Begin with the question the diagram is supposed to support. An example might be: explain how a caregiver connection differs from a parent connection in a fictional three-generation map. That purpose requires much less information than a detailed family history. A useful scope statement also says what will not be included, such as health notes, exact dates, addresses, and identifying photographs.

Name the intended reader before choosing fields or symbols. A person helping revise the source notes may need context that a classroom audience should never receive. A map intended for one discussion should not quietly become a general family dossier. If the purpose changes, revisit the information collected and the sharing decision instead of assuming that a previous approval covers every future use.

| Worksheet field | Fictional example |
| --- | --- |
| Purpose | Demonstrate structural and caregiving connections |
| Intended readers | Participants in a diagram-reading exercise |
| Included information | Invented names, approximate generations, connection labels |
| Excluded information | Real health records, contact details, identifying dates |
| Reading copy | A small image with a visible legend |

## 2. Keep a source ledger outside the picture

A line on a canvas is a compressed claim. Preserve the fuller explanation in a separate ledger so that someone can distinguish a source statement from an editing choice. Each row should identify the assertion, the note supporting it, the current uncertainty, and any sharing restriction. A source label is useful only if the reviewer can actually locate and interpret the associated note.

For fictional exercises, label every source as invented. Do not introduce a real person's history simply because the worksheet has room for another row. For other projects, collect only what the purpose genuinely requires and review the relevant privacy practices before storing or uploading it. Changing names does not necessarily anonymize a distinctive combination of dates, events, and relationships.

| Claim key | Assertion | Source reference | Review state |
| --- | --- | --- | --- |
| C01 | Rowan is a caregiver for Quinn | Fictional note A | Confirm the intended symbol |
| C02 | A partnership ended before the diagram date | Fictional note B | Approximate timing only |
| C03 | A relationship is not specified | No supporting statement | Leave unresolved |

## 3. Review people before reviewing lines

Check that every intended person is represented once. Two people sharing a first name should remain distinct, while a nickname should not automatically create an additional person. Use stable identifiers in the working material if the drawing tool supports them. The visible label can remain readable without becoming the only way to identify a node during correction.

Look for precision that the source did not provide. A note describing an event as occurring around a certain year should not become an exact date because a form accepts a complete date. An unknown age should stay unknown. A visually balanced layout is not a reason to add a person, merge two people, or move someone into a different generation without supporting information.

A simple pass can ask whether each visible person has a corresponding ledger entry or a clear reason to be included. Record unresolved identity questions beside the working draft rather than hiding them in a private memory. This helps another reviewer understand why a node remains incomplete and prevents a later editing session from treating an empty field as a request to guess.

## 4. Check each connection in both directions

Trace a line from its first endpoint to its second endpoint and read the label aloud. Then ask whether reversing that reading would change its meaning. A partnership may be represented differently from a parent connection, and a caregiving relationship should not silently become a biological assertion. The diagram's chosen convention needs to preserve those distinctions rather than relying on the reader to infer them.

Separate a missing source from a contradictory source. If no note specifies the relationship, retain that gap. If two notes disagree, record the disagreement for review. Neither situation is resolved by choosing whichever connection produces the simplest drawing. Avoid presenting an unresolved claim as settled merely because the application requires a color, line style, or position before the map looks tidy.

Before accepting a connection, check its endpoints, relationship type, relevant time context, and source reference. These are ordinary review questions, not a complete validation algorithm. Family structures vary, and a worksheet should not enforce assumptions about household size, gender, legal status, or which relationships are considered important. Representation choices should be documented and appropriate to the actual purpose.

## 5. Treat emotional notes as contextual descriptions

Structural connections and emotional descriptions answer different questions. A reported feeling of closeness, distance, or conflict may relate to a particular time or situation. It should not become a permanent diagnosis or a comprehensive statement about a person. Keep source and timing context where that information is necessary for the intended reader, and omit details that are not needed for the discussion.

An emotional line also needs a legend. Ask someone unfamiliar with the draft what they think the line means before explaining it. If they give a different interpretation, improve the label or simplify the visual convention. A design that only its author understands is not yet an effective communication tool, regardless of how attractive the colors and spacing appear.

## 6. Keep AI suggestions separate from evidence

When AI helps arrange an initial map, treat the result as a proposed draft. Compare the people and connections against the source ledger rather than checking only whether the canvas looks complete. A fluent explanation of a suggested connection is not a source for that connection. The review should make unsupported additions easier to reject, not harder to notice.

Useful drafting constraints can prohibit invented relatives, inferred diagnoses, and more precise dates than the notes supply. They can also ask for unresolved relationships to remain unresolved. Such instructions do not guarantee correct output. Their value is that they establish a reviewable expectation against which the actual draft can be inspected. Keep an editable starting point so that corrections do not depend on reconstructing an earlier version from an image.

## 8. Prepare a reading copy deliberately

Arrange the map for its eventual reading size rather than only for the editing canvas. Follow several representative connections and check that crossings do not make their endpoints ambiguous. Keep labels and the legend legible when printed or viewed on a smaller screen. If the complete map becomes too dense, make a focused view and explain what has been omitted instead of shrinking every label.

Reopen the exported file before sharing it. Check the title, revision date, legend, a representative branch, and the final notes. An export completing successfully only demonstrates that a file was produced. It does not prove that the intended content is present or that private working notes were excluded. Keep an editable backup separately when appropriate, but do not distribute it automatically with every reading copy.

## 9. Record the handoff and the next correction

Attach a short handoff note describing the purpose, intended audience, known uncertainties, and where corrections belong. If the document will be discussed with others, provide a respectful way to say that a detail is inaccurate, contested, or should not be included. The point of review is to improve the representation, not to defend an earlier layout because time was spent generating it.

| Handoff check | Decision to record |
| --- | --- |
| Audience | Who should receive this particular copy? |
| Uncertainty | Which assertions remain unresolved? |
| Omission | What information was intentionally left out? |
| Revision | Which working version produced the image? |
| Correction | Where should a disputed detail be recorded? |

When a correction arrives, identify the affected claims, connections, notes, and exported copies. Record what changed and why, while avoiding unnecessary replication of sensitive information in a revision log. If health interpretation is involved, seek qualified professional guidance and relevant evidence. A relationship diagram does not diagnose a condition, prove an inheritance pattern, or predict an individual's future health.

The final measure of a useful map is not how complete it looks. It is whether readers can understand its conventions, important assertions can be explained, uncertainty remains visible, and the shared information is proportionate to the purpose. These worksheets are a starting structure for that work, not an automated verdict that a family history is ready to publish.
